# VIBECODE NIGHTS — командный режим на Claude Code

Схема: у каждого свой Claude Code, общий репозиторий, задачи в `TASKS.md`, правила в `CLAUDE.md`.
Всё работает в ветке `main` маленькими коммитами: на один вечер ветки и пул-реквесты только мешают.

## Кейс вечера

**[«Злой инвестор»](docs/case/README.md)**: ИИ-тренажёр, который задаёт студенту 5 вопросов, ставит оценку по критериям «Стартап как диплом» и даёт 3 совета. Там же оригинал [PDF](docs/case/zloy-investor.pdf), карточки инвесторов, вопросы с предзащит и ссылка на датасет питчей. Сдаём прототип, one-pager и **открытый** репозиторий с README.

## Кто есть кто и что читать ИИ

Общий справочник участников: **[team-directory/](team-directory/README.md)**. В нём имена, точные GitHub-логины и готовое сообщение для подключения своего ИИ. Машиночитаемый состав — [members.json](team-directory/members.json).

Перед работой ИИ читает [AGENTS.md](AGENTS.md), [CLAUDE.md](CLAUDE.md), [docs/COMMS.md](docs/COMMS.md), справочник команды и [TASKS.md](TASKS.md). После обновления репозитория начните новую сессию ИИ или явно попросите его перечитать эти файлы.

## Подключение к каналу агентов

У всех участников уже есть доступ: пять человек и шесть GitHub-аккаунтов, два из них принадлежат Ратмиру. Каждому коллеге нужно выполнить пять шагов. Команды запускайте в локальной копии репозитория; GitHub CLI (`gh`) должен быть установлен.

### 1. Войти в GitHub CLI

```bash
gh auth login
```

Выберите GitHub.com → HTTPS → вход через браузер. Затем проверьте:

```bash
gh auth status
```

В выводе должен быть ваш активный логин из [справочника команды](team-directory/README.md). Вход в браузер GitHub или в редактор сам по себе не подтверждает вход в `gh`.

### 2. Обновить общую ветку

```bash
git switch main
git pull --rebase
```

Если Git сообщает о незавершённых изменениях или конфликте, разберитесь по `CLAUDE.md`, сохранив работу обеих сторон. После обновления в папке должен быть `docs/COMMS.md`.

### 3. Начать новую сессию агента

Закройте старую сессию и запустите `claude` или `codex` заново в папке репозитория. В десктоп-приложении начните новую сессию с этим репозиторием. Codex собирает цепочку проектных инструкций при старте, поэтому новая сессия подхватит обновлённые правила ([официальная документация](https://learn.chatgpt.com/docs/agent-configuration/agents-md)).

Первым сообщением отправьте:

```text
Меня зовут <Имя>, мой GitHub — <логин>.
Прочитай AGENTS.md, CLAUDE.md, docs/COMMS.md, team-directory/README.md и TASKS.md.
Отметься в канале агентов (issue #1) и возьми свободную задачу по правилам.
```

Агент должен написать в [issue #1 «Канал агентов»](https://github.com/Vlad1768/vibecode_nights/issues/1):

```text
[<Имя>-<ИИ> → все] online
```

Подпись должна совпадать с принятой в `TASKS.md` и `docs/COMMS.md`. Иван использует `Ivan-Claude`; Герман с Codex — `Герман-Codex` (существующая запись `герман-Codex` относится к тому же человеку). Если комментарий появился, запись в канал работает.

### 4. Сохранить разрешения для рабочих команд

Когда агент запрашивает разрешение, проверяйте команду. Если инструмент предлагает «разрешать всегда» для этой команды или её префикса, сохраните разрешение для чтения и комментариев issue #1 этого репозитория и обычных Git-операций по `CLAUDE.md`, чтобы не подтверждать каждую проверку канала заново.

Названия кнопок зависят от инструмента. В Codex CLI доступами можно управлять через `/permissions` ([справочник команд](https://learn.chatgpt.com/docs/cli/slash-commands)). Постоянные разрешения не отменяют запреты команды на force push, `reset --hard` и удаление чужих файлов.

### 5. Организовать регулярную проверку канала

**Claude Code:** если доступна команда `/loop`, один раз для текущей рабочей сессии отправьте:

```text
/loop 5m проверь канал агентов по docs/COMMS.md, ответь на адресованное мне и продолжай свою задачу
```

Убедитесь, что Claude подтвердил создание задания. Для проверок нужны работающие компьютер и процесс Claude Code; если агент занят, проверка дождётся завершения текущего хода. При недоступном `/loop` используйте ручную проверку ([документация Claude Code](https://code.claude.com/docs/en/scheduled-tasks)).

**Codex:** по принятому в `docs/COMMS.md` порядку человек раз в несколько минут отправляет:

```text
Проверь сообщения в канале агентов по docs/COMMS.md, ответь на адресованное мне и продолжай свою задачу.
```

Между ходами чата автоматическое чтение канала этим сообщением не запускается.

**Как проверить всю команду:** когда в #1 отметится агент каждого из пяти людей, задайте агенту коллеги короткий вопрос по формату из `docs/COMMS.md` и дождитесь ответа при его следующей проверке. Два аккаунта Ратмира считаются одним человеком. Задачи и их статусы остаются в `TASKS.md`, переписка — в issue #1.

Для этого вечера работайте локально: в терминале или десктоп-приложении. Сессия Claude Code в браузере может пушить в свою ветку `claude/...`; её изменения не появляются в общем `main` автоматически. Наличие комментария в канале не заменяет успешный захват задачи и пуш в общую ветку.

## Что сделать до вечера (каждый участник)

- [ ] Аккаунт на GitHub, ник отправить ведущему.
- [ ] **Принять приглашение** в репозиторий (придёт на почту / github.com/notifications). Без этого пуш не пройдёт — самая частая проблема.
- [ ] Установлен Claude Code, выполнен вход, в `/model` выбран Opus.
- [ ] Git настроен: `git config --global user.name "Имя"` и `user.email`.
- [ ] Работает пуш на GitHub (вход через `gh auth login` или SSH-ключ). Проверка — разминка ниже.
- [ ] Склонировать репозиторий и запустить `claude` в его папке.

## Ведущий: подготовка

1. Settings → Collaborators → добавить всех участников с правом Write.
2. Смёржить этот набор в `main` (или скопировать файлы в новый репозиторий).
3. По желанию: Settings → Branches → запретить force push в `main`.

## Сценарий вечера

| Время | Что происходит |
|---|---|
| 0:00–0:10 | Объявили задание. Ведущий решает: что делаем, стек, на какие части режем |
| 0:10–0:40 | Ведущий со своим Claude делает каркас: пустой проект, папки, `docs/CONTRACT.md`, раздел «Проект» в `CLAUDE.md`, 8–15 задач в `TASKS.md`. Остальные в это время делают разминку и обсуждают идеи |
| 0:40 | Ведущий пушит каркас, все делают `git pull` |
| 0:40–2:30 | Каждый: «возьми свободную задачу» → делает → «готово» → следующая |
| каждые ~40 мин | Круг ревью: каждый просит своего Claude проверить коммиты соседа |
| 2:30–3:00 | Заморозка: новые задачи не берём, только фиксы и сборка демо |

## Как ведущему нарезать задачи

- Одна задача — 20–40 минут работы Claude, с понятным результатом («страница списка показывает моки из `mock.json`»).
- У каждой задачи своя папка или свои файлы в колонке «Где». Две задачи не правят один файл одновременно.
- Сначала задачи без зависимостей, чтобы все сразу начали параллельно. Данные стыкуем через `docs/CONTRACT.md` и моки, а не ждём друг друга.
- Одна задача «Интеграция» в конце — её берёт ведущий.

## Фразы для своего Claude

Начать:
```
Меня зовут <Имя>. Прочитай CLAUDE.md, сделай git pull, возьми свободную задачу из TASKS.md по правилам и делай её.
```

Закончил задачу:
```
Отметь задачу готовой в TASKS.md по правилам, запушь и возьми следующую свободную.
```

Ревью:
```
Сделай git pull и посмотри последние коммиты <Имя коллеги>. Найди ошибки и расхождения с docs/CONTRACT.md. Мелкое исправь, крупное добавь задачей в TASKS.md.
```

Если что-то сломалось:
```
git pull не проходит / конфликт. Разберись, сохрани изменения обеих сторон, ничего не удаляй и не делай force push.
```

## Разминка (завтрашняя репетиция, 15 минут)

Задачи `R1`–`R5` в `TASKS.md`. Все одновременно говорят своему Claude «возьми свободную задачу». Что проверяем:

1. Доступ: у всех прошёл пуш.
2. Гонка за задачу: двое схватили одну строку — второй Claude должен увидеть отказ пуша, сделать `pull --rebase` и выбрать другую.
3. Конфликт: все дописывают строку в общий `team/README.md` — Claude должен склеить, а не затереть чужое.

В конце в `team/README.md` должны быть все имена, а в `TASKS.md` все R-задачи `готово`. Если так — схема работает.

## Если используете Claude Code в браузере (claude.ai/code)

Облачная сессия пушит в свою ветку `claude/...`, а не в `main`, поэтому общий `TASKS.md` не обновится у остальных. Для вечера лучше Claude Code в терминале или десктоп-приложении на своём компьютере.

## Меньше запросов разрешений (по желанию)

Каждый может создать у себя `.claude/settings.local.json`, чтобы Claude не спрашивал про каждую git-команду:

```json
{
  "permissions": {
    "allow": ["Bash(git status:*)", "Bash(git pull:*)", "Bash(git log:*)", "Bash(git diff:*)",
              "Bash(git show:*)", "Bash(git add:*)", "Bash(git commit:*)", "Bash(git push)"],
    "deny": ["Bash(git push --force:*)", "Bash(git push -f:*)", "Bash(git reset --hard:*)"]
  }
}
```
