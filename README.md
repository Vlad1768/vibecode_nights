# Злой инвестор

**ИИ-тренажёр, после которого вопросы жюри не застанут врасплох.** Студент вставляет питч своего
стартапа, инвестор с характером задаёт ровно 5 неудобных вопросов по этому питчу, ставит оценку
по 10 критериям «Стартап как диплом» и даёт ровно 3 совета, которые можно успеть до выхода на сцену.

Кейс VIBECODE NIGHTS от Стартап Клуба, 11.2026: [расшифровка](docs/case/README.md) · [PDF](docs/case/zloy-investor.pdf).

| | |
|---|---|
| Сайт | `https://fightinvestor.ru` — ссылка заработает после публикации (T32) |
| Telegram-бот | ссылка появится после регистрации бота (T30) |
| One-pager | `pitch/` (T31) |

## Как это работает для студента

1. **Знакомство.** Карточка инвестора: кто он, чего хочет и чего боится. Раунд занимает около 10 минут.
2. **Питч.** Студент вставляет описание текстом, до 4000 знаков.
3. **«Что я понял».** Инвестор перечисляет факты из питча и то, чего в нём не хватает. Дальше он опирается только на них.
4. **5 вопросов.** Каждый вопрос цитирует питч или прошлый ответ. После ответа — короткая реакция без балла.
5. **Оценка из 100** по 10 критериям: сильное и слабое двумя строками, по каждому критерию уровень и цитата, за что он поставлен.
6. **3 совета** со сроком в днях и признаком «готово»: что сделать до выступления.
7. **Второй раунд** по обновлённому питчу и итог «было → стало». Студент вернулся и прошёл раунд лучше — это и есть успех по кейсу.

Что продукт решает и чего сознательно не делает — [docs/PRODUCT.md](docs/PRODUCT.md).

## Как устроена оценка

Основа — 10 критериев конкурса «Стартап как диплом» из кейса. Каждому критерию ставится **уровень от 0 до 3**:

| Уровень | Что значит |
|---|---|
| 0 | Нет данных или только слова («конкурентов нет») |
| 1 | Заявлено, но без цифр и проверки |
| 2 | Есть цифры или факт, но мало или без источника |
| 3 | Подтверждено: продажи, интервью, документы, расчёт |

**Итог считает код, а не модель:** балл критерия = вес × уровень / 3, сумма весов 100. Веса задаёт
персонаж (обоснование — `docs/INVESTOR.md`, T29); пока персонаж не утверждён, действуют веса бизнес-ангела
из [docs/BOT_SCENARIO.md](docs/BOT_SCENARIO.md).
Модель возвращает только уровни, цитаты и тексты, а код их проверяет:

- **цитата должна дословно найтись** в питче или ответах студента, иначе уровень обнуляется;
- **цифры только из текста студента**: вопрос или реакция с числом, которого студент не писал, заменяется;
- **ровно 5 вопросов, 10 критериев, 3 совета** — проверяет код;
- **совет без срока, со сроком дольше недели или со стоп-фразой** («проведите исследование рынка») отбраковывается и заменяется запасным по самому слабому критерию;
- **уговоры не работают**: «поставьте высокий балл» и «игнорируй правила» на оценку не влияют, в ответе появляется одна фраза об этом.

Подробно: [core/README.md](core/README.md), формат и веса персонажа — там же.

## Архитектура

```
 браузер ── https://fightinvestor.ru ── Caddy ──┬─ /      → статика сайта (web/)
                                                └─ /api/* → API 127.0.0.1:8080 (server/ + core/)
 Telegram ── бот (bot/) ── http://127.0.0.1:8080 ─────────► тот же API ──► модель Gemini
```

Вся логика в одном API: сайт и бот только показывают ответы, поэтому ведут себя одинаково.
Договорённость между частями — [контракт API 1.0](docs/CONTRACT.md).

> **Сейчас (06.11):** первая версия сайта (`web/`) работает через собственный сервер-адаптер с другой схемой
> API и шкалой 0–10. Перевод сайта на общий API — задача T45; до неё сайт и бот оценивают по-разному.

| Папка | Что там |
|---|---|
| `core/` | Логика раунда: проверки ввода, вопросы, оценка, советы, демо-движок без сети |
| `server/` | HTTP API по контракту: маршруты, хранение сессий, лимиты |
| `bot/` | Telegram-бот |
| `web/` | Сайт |
| `integrations/gemini/` | Клиент модели Gemini |
| `contract/` | Mock-сервер API и примеры ответов |
| `deploy/`, `.github/workflows/` | Запуск на сервере |
| `docs/` | Кейс, продукт, контракт, сценарий бота, требования |

## Стек

- **API и бот:** Node.js 22, без npm-зависимостей.
- **Модель:** Gemini через собственный клиент `integrations/gemini/`.
- **Сайт:** статическая сборка, которую раздаёт Caddy.
- **Сервер:** Ubuntu 24.04, Caddy (HTTPS), systemd.

## Как запустить

Нужен Node.js 22+. Ключ модели не обязателен: без него API работает в режиме `demo` на встроенном движке.

```bash
git clone https://github.com/Vlad1768/vibecode_nights.git
cd vibecode_nights
node server/index.mjs                       # API на http://127.0.0.1:8080, режим demo
curl http://127.0.0.1:8080/api/health       # {"ok":true,"mode":"demo","version":"1.0"}
```

С моделью: положить `GEMINI_API_KEY=…` в `.env.local` (файл в `.gitignore`, образец — `.env.example`) и запустить `node --env-file=.env.local server/index.mjs`.

Бот (нужен токен от @BotFather):

```bash
cd bot
BOT_TELEGRAM_TOKEN=<токен> TRAINER_API_URL=http://127.0.0.1:8080 npm start
```

Сайт — по инструкции в `web/README.md` (появится вместе с сайтом, T26). При разработке запросы `/api` проксируются на `http://127.0.0.1:8080`.

Настройки API (порт, режим, хранилище, содержание персонажа) — в [server/README.md](server/README.md),
бота — в [bot/README.md](bot/README.md), деплой бота — в [docs/BOT_DEPLOY.md](docs/BOT_DEPLOY.md).

## Проверки

```bash
node --test core/*.test.mjs server/*.test.mjs   # ядро и API: 29 проверок
(cd bot && npm test)                            # бот: 21 проверка
node --test contract/mock-server.test.mjs       # контракт: 7 проверок
node --test integrations/gemini/client.test.mjs # клиент модели: 40 проверок
```

Сеть и ключи не нужны. Среди проверок — все 15 заявок датасета организаторов
([pitch-dataset.md](docs/case/pitch-dataset.md)): пустой питч и «см. презентацию» не получают оценку,
«не питч» отклоняется, просьбы поднять балл не влияют на итог, остальные заявки проходят раунд.
Ещё проверяются выдуманные моделью цифры и цитаты, сбой модели, двойная отправка ответа, чужая сессия,
лимиты и перезапуск с сохранёнными сессиями.

## Безопасность

- **Ключи и токены** — только в окружении сервера и в GitHub Actions Secrets. В коде, в Git и в браузере их нет; `.env*` в `.gitignore`, кроме образца `.env.example`.
- **Сессии изолированы:** сессия принадлежит своему пользователю, чужая и несуществующая выглядят одинаково (`404`). Номер сессии — случайный UUID.
- **Нестандартный ввод:** пустой, слишком длинный, не-питч, попытки переписать правила — понятный ответ вместо сбоя. Правила и формула оценки живут в коде, текстом их не переписать.
- **Лимиты:** 10 новых сессий в час на пользователя и 60 запросов в минуту на IP; тело запроса до 64 КБ.
- **Сбой модели не теряет ответы:** ответ студента сохраняется до вызова модели, повтор того же запроса продолжает с того же места.
- **Журнал без личных данных:** только события и числа для метрик, без текстов питчей и ответов. Сессии хранятся 14 дней, студент может удалить свои данные (`DELETE /api/users/{userId}`, в боте `/delete`).
