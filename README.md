# VIBECODE NIGHTS — командный режим на Claude Code

Схема: у каждого свой Claude Code, общий репозиторий, задачи в `TASKS.md`, правила в `CLAUDE.md`.
Всё работает в ветке `main` маленькими коммитами: на один вечер ветки и пул-реквесты только мешают.

## Что сделать до вечера (каждый участник)

- [ ] Аккаунт на GitHub, ник отправить ведущему.
- [ ] **Принять приглашение** в репозиторий (придёт на почту / github.com/notifications). Без этого пуш не пройдёт — самая частая проблема.
- [ ] Установлен Claude Code, выполнен вход, в `/model` выбран Opus.
- [ ] Git настроен: `git config --global user.name "Имя"` и `user.email`.
- [ ] Работает пуш на GitHub (вход через `gh auth login` или SSH-ключ). Проверка — разминка ниже.
- [ ] Склонировать репозиторий и запустить `claude` в его папке.

## Ведущий: подготовка

1. Settings → Collaborators → добавить всех участников с правом Write.
2. Смёржить этот набор в `main` (или скопировать файлы в новый репозиторий).
3. По желанию: Settings → Branches → запретить force push в `main`.

## Сценарий вечера

| Время | Что происходит |
|---|---|
| 0:00–0:10 | Объявили задание. Ведущий решает: что делаем, стек, на какие части режем |
| 0:10–0:40 | Ведущий со своим Claude делает каркас: пустой проект, папки, `docs/CONTRACT.md`, раздел «Проект» в `CLAUDE.md`, 8–15 задач в `TASKS.md`. Остальные в это время делают разминку и обсуждают идеи |
| 0:40 | Ведущий пушит каркас, все делают `git pull` |
| 0:40–2:30 | Каждый: «возьми свободную задачу» → делает → «готово» → следующая |
| каждые ~40 мин | Круг ревью: каждый просит своего Claude проверить коммиты соседа |
| 2:30–3:00 | Заморозка: новые задачи не берём, только фиксы и сборка демо |

## Как ведущему нарезать задачи

- Одна задача — 20–40 минут работы Claude, с понятным результатом («страница списка показывает моки из `mock.json`»).
- У каждой задачи своя папка или свои файлы в колонке «Где». Две задачи не правят один файл одновременно.
- Сначала задачи без зависимостей, чтобы все сразу начали параллельно. Данные стыкуем через `docs/CONTRACT.md` и моки, а не ждём друг друга.
- Одна задача «Интеграция» в конце — её берёт ведущий.

## Фразы для своего Claude

Начать:
```
Меня зовут <Имя>. Прочитай CLAUDE.md, сделай git pull, возьми свободную задачу из TASKS.md по правилам и делай её.
```

Закончил задачу:
```
Отметь задачу готовой в TASKS.md по правилам, запушь и возьми следующую свободную.
```

Ревью:
```
Сделай git pull и посмотри последние коммиты <Имя коллеги>. Найди ошибки и расхождения с docs/CONTRACT.md. Мелкое исправь, крупное добавь задачей в TASKS.md.
```

Если что-то сломалось:
```
git pull не проходит / конфликт. Разберись, сохрани изменения обеих сторон, ничего не удаляй и не делай force push.
```

## Разминка (завтрашняя репетиция, 15 минут)

Задачи `R1`–`R5` в `TASKS.md`. Все одновременно говорят своему Claude «возьми свободную задачу». Что проверяем:

1. Доступ: у всех прошёл пуш.
2. Гонка за задачу: двое схватили одну строку — второй Claude должен увидеть отказ пуша, сделать `pull --rebase` и выбрать другую.
3. Конфликт: все дописывают строку в общий `team/README.md` — Claude должен склеить, а не затереть чужое.

В конце в `team/README.md` должны быть все имена, а в `TASKS.md` все R-задачи `готово`. Если так — схема работает.

## Если используете Claude Code в браузере (claude.ai/code)

Облачная сессия пушит в свою ветку `claude/...`, а не в `main`, поэтому общий `TASKS.md` не обновится у остальных. Для вечера лучше Claude Code в терминале или десктоп-приложении на своём компьютере.

## Меньше запросов разрешений (по желанию)

Каждый может создать у себя `.claude/settings.local.json`, чтобы Claude не спрашивал про каждую git-команду:

```json
{
  "permissions": {
    "allow": ["Bash(git status:*)", "Bash(git pull:*)", "Bash(git log:*)", "Bash(git diff:*)",
              "Bash(git show:*)", "Bash(git add:*)", "Bash(git commit:*)", "Bash(git push)"],
    "deny": ["Bash(git push --force:*)", "Bash(git push -f:*)", "Bash(git reset --hard:*)"]
  }
}
```
