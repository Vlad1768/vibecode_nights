# VIBECODE NIGHTS — командный режим на Claude Code

Схема: у каждого свой Claude Code, общий репозиторий, задачи в `TASKS.md`, правила в `CLAUDE.md`, ускорители в `.claude/skills/` (скиллы) и `scripts/` (скрипты).
Всё работает в ветке `main` маленькими коммитами: на один вечер ветки и пул-реквесты только мешают.

## Скиллы: что вводить своему Claude

| Команда | Кто | Когда | Что делает |
|---|---|---|---|
| `/ideate <кейс>` | все пятеро параллельно | 0:00–0:08 | разбор кейса, 3 концепта с оценкой, wow-момент, сценарий демо |
| `/kickoff <кейс + идея>` | ведущий | 0:08–0:28 | PRODUCT.md, каркас Next.js, CONTRACT.md, общие заготовки, DESIGN.md, 10–15 задач, пуш |
| `/next <Имя>` | все | весь хакатон | взять задачу (без гонок), сделать, проверить, закрыть, взять следующую |
| `/peer-review <имя>` | все, Codex особенно | каждые ~40 мин | ревью коммитов коллеги: сборка, контракт, баги, секреты |
| `/polish <маршрут>` | фронты | после экранов | дизайн-направление и доводка UI по скриншотам |
| `/ai-feature <что>` | бэк/AI | задача с AI | LLM-функция по готовым шаблонам с демо-режимом |
| `/demo-data <что>` | любой | задача с данными | правдоподобные данные и «герой» демо |
| `/smoke` | ведущий | каждые 30–40 мин | весь main: сборка, скриншоты всех страниц, демо-сценарий |
| `/deploy` | ведущий | сразу после каркаса | Vercel из GitHub (автодеплой), запасной туннель, QR |
| `/pitch` | продукт/питч | с 0:30 | слайды `pitch/index.html`, текст, план Б, вопросы жюри |
| `/freeze <мин>` | ведущий | за 35 мин до конца | заморозка, фиксы, финальный деплой, чек-лист, репетиция |

Скрипты под капотом (их же можно звать руками):
- `bash scripts/tasks.sh free | status | claim T3 Имя | done T3 Имя "заметка" | add "…" "где" | block | release` — работа с `TASKS.md` с защитой от гонок (проверено на 5 одновременных захватах).
- `node scripts/shot.mjs / /маршрут` — скриншоты на десктопе и мобильном в `.shots/` плюс ошибки консоли. Claude сам смотрит картинки и правит UI.

Для Codex то же самое описано в `AGENTS.md`, копия скиллов — в `.agents/skills/`. После правки скиллов запускай `bash scripts/sync-agents-skills.sh`.

## Что сделать до вечера (каждый участник)

- [ ] Аккаунт на GitHub, ник отправить ведущему.
- [ ] **Принять приглашение** в репозиторий (придёт на почту / github.com/notifications). Без этого пуш не пройдёт — это самая частая проблема.
- [ ] Установлен Claude Code, выполнен вход, в `/model` выбран Opus.
- [ ] Node.js 20+ (`node -v`). На Windows — **Git for Windows** (Git Bash нужен скриптам и Claude Code).
- [ ] Git настроен: `git config --global user.name "Имя"` и `user.email`.
- [ ] Работает пуш на GitHub (вход через `gh auth login` или SSH-ключ). Проверка — разминка ниже.
- [ ] Склонировать репозиторий и запустить `claude` в его папке.
- [ ] Скриншоты для визуальной проверки (один раз, ~1 мин): `npm i -g playwright && playwright install chromium`. Проверка — `node scripts/shot.mjs --base https://example.com /` создаёт `.shots/home-desktop.png`.
- [ ] Человек с Codex: установлен Codex CLI, сделан отдельный клон репозитория для него (см. «Если у тебя Codex»).

## Ведущий: подготовка

1. Settings → Collaborators → добавить всех участников с правом Write.
2. Смёржить этот набор в `main`.
3. По желанию: Settings → Branches → запретить force push в `main`.
4. **API-ключ для AI внутри продукта**: подписка Max его не даёт. Нужен ключ из console.anthropic.com с балансом $5–10 (или выданный организаторами). Без ключа всё работает в демо-режиме на заготовленных ответах.
5. **Vercel**: зайти на vercel.com через GitHub и проверить, что репозиторий виден при импорте. Сам проект создаётся на хакатоне за 2 минуты (`/deploy`).
6. Запасной туннель: один раз выполнить `npx -y cloudflared tunnel --url http://localhost:3000`, чтобы бинарник скачался заранее.
7. По желанию — общие разрешения, чтобы Claude не спрашивал про каждую git- и npm-команду: скопировать `docs/claude-settings.example.json` в `.claude/settings.json` и закоммитить. Внутри разрешены git, npm и скрипты команды, а force push и `reset --hard` запрещены.

## Сценарий вечера (3 часа)

| Время | Ведущий | Остальные |
|---|---|---|
| 0:00–0:08 | читает кейс, `/ideate` | все запускают `/ideate <кейс>` параллельно, приносят лучшую идею |
| 0:08–0:10 | выбор идеи (2 минуты, решает ведущий) | — |
| 0:10–0:28 | `/kickoff <кейс + идея>` — каркас, контракт, задачи, пуш | питч: структура и текст (`/pitch`); остальные: окружение, playwright, черновик данных и промптов в чате (не в репозитории) |
| 0:28 | «Каркас в main» | `git pull && cd web && npm install && cp .env.example .env.local`, затем `/next <Имя>` |
| 0:30–0:40 | `/deploy`: ссылка живёт с первых минут | работа по `/next` |
| 0:40–2:25 | интеграция, `/smoke` каждые 30–40 мин, разбор блоков | `/next` по кругу; круги ревью `/peer-review` на ~1:10 и ~1:50 |
| 1:30 | — | питч: реальные скриншоты, QR, репетиция текста |
| 2:25 | `/freeze 35` — заморозка | только фиксы из списка ведущего |
| 2:45 | финальный деплой и чек-лист | запись экрана демо (план Б) |
| 2:50–3:00 | две репетиции с таймером | никто не пушит в main |

### Роли на старте (дальше все просто берут `/next`)
- **Ведущий**: kickoff, деплой, интеграция, smoke, заморозка.
- **Фронт ×2**: экраны демо-сценария, потом `/polish`.
- **Бэк/AI**: AI-функция (`/ai-feature`), данные и API.
- **Продукт и питч** (удобно — человек с Codex): `/pitch` с 0:10, `/demo-data`, ревью и QA. Codex — независимый ревьюер: у другой модели другие слепые зоны.

## Если у тебя Codex

Готовая инструкция «скопировал и вставил» — `docs/codex-start.md`.

С GitHub Codex работает так же, как Claude Code: через обычный git на твоём компьютере. Общий репозиторий и `TASKS.md` одни на всех, неважно, какой агент пушит.

0. **Установка (один раз):** `npm i -g @openai/codex` (на macOS можно `brew install --cask codex`), затем `codex` и в первом окне **Sign in with ChatGPT** — вход аккаунтом с подпиской. Отдельно «подключать GitHub к Codex» не нужно: он пушит через git этого компьютера. Достаточно, чтобы работали `gh auth login` (или SSH-ключ) и принятое приглашение в репозиторий.
1. **Codex CLI или расширение в IDE, локально.** Не Codex Cloud: облачные задачи пушат в отдельные ветки и PR, и `TASKS.md` у команды не обновится (та же история, что с claude.ai/code).
2. **Отдельная папка для Codex**, если параллельно работает и твой Claude Code: `git clone <url репозитория> vibecode_nights-codex`. Тогда два агента не правят одни файлы и не мешают друг другу в git.
3. Запусти `codex` в этой папке. Он сам прочитает `AGENTS.md`: там правила, скрипты и список скиллов.
4. **Скиллы**: `$next Маша`, `$peer-review all`, `$smoke`, `$pitch` (или `/skills` и выбрать из списка). Фраза «/next Маша» тоже сработает: `AGENTS.md` объясняет, какой файл открыть.
5. **Сеть.** По умолчанию песочница Codex без интернета, поэтому `git push` и `npm install` будут просить подтверждения. Подтверждай. Чтобы не спрашивал, добавь в `~/.codex/config.toml`:
   ```toml
   [sandbox_workspace_write]
   network_access = true
   ```
   (на macOS это иногда не срабатывает, тогда просто подтверждай).
6. **Имя в TASKS.md**: если задачу берёт Codex, пиши `Маша-Codex`, чтобы было видно, кто её делает.

Лучшая роль Codex в команде — **независимый ревьюер**: у другой модели другие слепые зоны. Каждые ~40 минут `$peer-review all`, перед деплоем `$smoke`, в свободное время исследование для питча. Обычные задачи — через `$next`.

## Как ведущему нарезать задачи

Подробно с типовым набором — в `.claude/skills/kickoff/slicing.md`. Кратко:
- Одна задача — 20–40 минут работы Claude, с понятным результатом («страница списка показывает моки из `api.ts`»).
- У каждой задачи своя папка или свои файлы в колонке «Где». Две задачи не правят один файл одновременно.
- Сначала задачи без зависимостей, чтобы все сразу начали параллельно. Данные стыкуем через `docs/CONTRACT.md` и моки, а не ждём друг друга.
- Задачи «Интеграция» и «Деплой» берёт ведущий.

## Фразы для своего Claude (если не хочется слэш-команд)

Начать: `Меня зовут <Имя>. /next <Имя>`, или словами: «Прочитай CLAUDE.md, возьми свободную задачу из TASKS.md по правилам и делай её».
Работать без остановки: `/next <Имя> — работай по кругу, пока есть свободные задачи, после каждой коротко отчитывайся`.
Ревью: `/peer-review <Имя коллеги>`.
Если что-то сломалось: «git pull не проходит / конфликт. Разберись, сохрани изменения обеих сторон, ничего не удаляй и не делай force push».

## Разминка (завтрашняя репетиция, 15 минут)

Задачи `R1`–`R5` в `TASKS.md`. Все одновременно говорят своему Claude `/next <Имя>`. Что проверяем:

1. Доступ: у всех прошёл пуш.
2. Гонка за задачу: двое схватили одну строку — `scripts/tasks.sh` у второго увидит отказ пуша, сделает pull и скажет «ЗАНЯТО», а Claude выберет другую.
3. Конфликт: все дописывают строку в общий `team/README.md`. Claude должен склеить правки, а не затереть чужое.
4. Скриншоты: `node scripts/shot.mjs --base https://example.com /` создаёт `.shots/home-desktop.png`, значит playwright стоит.

В конце в `team/README.md` должны быть все имена, а в `TASKS.md` все R-задачи — `готово`. Если так, схема работает.

## Если используете Claude Code в браузере (claude.ai/code)

Облачная сессия пушит в свою ветку `claude/...`, а не в `main`, поэтому общий `TASKS.md` у остальных не обновится. Для вечера лучше Claude Code в терминале или десктоп-приложении на своём компьютере.

## Меньше запросов разрешений (по желанию)

Готовый список — `docs/claude-settings.example.json`. Его можно положить общим файлом (`.claude/settings.json`, см. «Ведущий: подготовка») или каждому себе в `.claude/settings.local.json` (не коммитится).
