# Правила командной работы (читать каждому Claude перед любым действием)

Над этим репозиторием одновременно работают несколько человек, у каждого свой Claude Code.
Общая память команды — этот репозиторий и файл `TASKS.md`. Других каналов у тебя нет.

## Цикл работы (строго по порядку)

1. `git pull --rebase` — всегда перед началом и перед каждым пушем.
2. Прочитай `TASKS.md` целиком. Возьми задачу со статусом `свободна`, у которой выполнены все зависимости (колонка «Зависит от»).
3. **Захват задачи — отдельным коммитом и сразу пуш:**
   - в строке задачи поменяй статус на `в работе: <Имя>` (имя спроси у человека, если не знаешь);
   - `git add TASKS.md && git commit -m "claim T<номер>: <Имя>" && git push`;
   - если пуш отклонён — `git pull --rebase`, проверь, не занял ли задачу кто-то другой. Занял — откати свою правку и выбери другую задачу.
   - Не начинай писать код, пока захват не запушен.
4. Делай задачу. Трогай только файлы и папки, указанные в колонке «Где». Нужно поменять чужое — см. раздел «Чужой код».
5. Коммить маленькими шагами. Перед каждым пушем: `git pull --rebase`, затем проверка (см. «Проверка»), затем `git push`.
6. Готово → в `TASKS.md` статус `готово: <Имя>`, в колонку «Заметки» одна строка: что сделано и как проверить. Коммит `done T<номер>`, пуш.
7. Скажи человеку, что задача закрыта, и предложи взять следующую.

## Жёсткие запреты

- Никаких `git push --force`, `git reset --hard` на общих ветках, удаления чужих файлов.
- Не переписывай `CLAUDE.md` и договорённости в `docs/CONTRACT.md` без согласия ведущего (поменял — напиши в «Журнал решений» внизу `TASKS.md`).
- Не меняй чужие строки в `TASKS.md`, кроме своих задач. Новые задачи добавляй в конец таблицы со статусом `свободна`.
- Не устанавливай новые зависимости без записи в «Журнал решений».
- Конфликт при rebase: разреши его, сохранив изменения ОБЕИХ сторон. Не понимаешь чужой код — останови работу и спроси человека.

## Чужой код

Нашёл ошибку в чужой части — не правь молча. Добавь в `TASKS.md` новую задачу «Фикс: …» с указанием файла, либо, если правка в одну-две строки и очевидна, сделай её отдельным коммитом `fix(<папка>): …` и упомяни в «Заметках» задачи автора.

## Проверка ревью («посмотри изменения коллеги»)

1. `git pull --rebase`, `git log --oneline -15`, `git show <коммит>` по коммитам коллеги.
2. Ищи: поломки запуска, расхождение с `docs/CONTRACT.md`, явные баги, забытые TODO.
3. Мелкое — исправь коммитом `review(<папка>): …`. Крупное — новая задача в `TASKS.md`.
