# /smoke — работает ли продукт целиком (≤10 минут)

Цель: «текст, который человек написал после команды». По умолчанию `all`: все маршруты и демо-сценарий.

## 1. Свежее состояние
```bash
git pull --rebase
cd web && npm install            # если менялся package.json/package-lock.json
npm run build                    # красная сборка — проблема №1, разберись первой
```

## 2. Запуск и снимки
Запусти продакшн-сервер в фоне (`npm run start`, порт 3000; dev-сервер тоже подойдёт). Собери маршруты:
```bash
find web/src/app -name "page.tsx" | sed -E 's#web/src/app##; s#/page.tsx##; s#^$#/#; s#/\([^)]*\)##g'
```
Динамические маршруты (`[id]`) подставь id героя из моков. Затем:
```bash
node scripts/shot.mjs / /route1 /route2/<id> ...
```
Посмотри **каждый** скриншот (Read `.shots/*.png`): десктоп и мобильный.

## 3. Демо-сценарий
Пройди шаги из `docs/PRODUCT.md`, раздел «Демо-сценарий». Для кликов и ввода напиши короткий одноразовый Playwright-скрипт в `.shots/flow.mjs`: открыть, кликнуть, ввести, дождаться результата, сделать скриншот. Он не коммитится. Проверь, что AI-шаг работает и в демо-режиме (без ключа).

## 4. Разбор
Таблица в чат:
```
| Маршрут/шаг | Десктоп | Мобильный | Консоль | Проблема | Чья зона (git log -1 -- <файл>) |
```
- **Сломано на пути демо** → чини сразу, если это интеграция (зона ведущего), или делай мелкий фикс `fix(<папка>): …`. Иначе `bash scripts/tasks.sh add "Фикс: …" "<файл>" "—"` и позови автора.
- **Некрасиво, но работает** → задача «Полировка: …».
- **Недоделанный экран вне демо** → предложи ведущему скрыть его из навигации до заморозки.

## 5. Итог человеку (≤8 строк)
Сборка ✓/✗ · сколько маршрутов OK из всех · демо-сценарий проходит / ломается на шаге N · заведены задачи T… · что исправлено.
