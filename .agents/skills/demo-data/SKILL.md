# /demo-data — данные, в которые жюри поверит

Цель: «текст, который человек написал после команды». Данные — половина впечатления от демо. Пустой или фальшивый экран убивает даже хороший продукт.

## Правила
1. **Строго по контракту.** Типы берутся из `web/src/lib/types.ts`, массивы типизированы (`export const orders: Order[] = […]`). Типы не меняй. Не хватает поля — скажи ведущему.
2. **Герой сценария.** Сначала вручную напиши 1–3 записи, вокруг которых идёт демо (`docs/PRODUCT.md`). Это конкретный человек или объект с историей, на котором видна проблема и её решение. Вынеси id в `export const DEMO_HERO_ID`. Остальные записи — фон.
3. **Объём**: 20–50 записей на главную сущность, чтобы списки, фильтры и графики выглядели живыми. Генерируй детерминированно, без `Math.random()` в рендере: либо готовым массивом, либо функцией с фиксированным сидом при загрузке модуля.
4. **Реализм.**
   - Имена разнообразные (русские, разного возраста и пола) и правдоподобные компании («ООО «Северный ветер»», «Кофейня на Лиговском»). Без «Иванов Иван Иванович» на каждой строке.
   - Суммы неровные (12 490, 3 180, 147 300), с распределением: много мелких, мало крупных.
   - Даты относительно «сейчас»: последние 30–90 дней, рабочие часы, плотнее в будни.
   - Статусы в реалистичных долях (например, 70% «выполнено», 20% «в работе», 10% «проблема»), и среди них есть интересные для демо случаи.
   - Тексты (отзывы, описания, комментарии) живые, разной длины, с опечатками в меру.
   - Есть пограничные случаи: длинное название, пустое необязательное поле, но не на пути демо.
5. **Картинки без внешних сервисов.** Аватары — инициалы на цветном фоне (цвет считается из хэша имени). Товары — иконки lucide или локальные файлы в `web/public/`. Хотлинки на сторонние сайты могут упасть на Wi-Fi площадки.
6. **AI-фикстуры** (если есть AI-функция) — в `web/src/data/ai-fixtures.ts`: идеальные ответы для героя, по форме совпадающие со схемой роута.

## Шаги
1. Прочитай контракт, PRODUCT.md (сценарий и герой) и существующий `web/src/data/`.
2. Напиши героев руками, затем фон (генератором или массивом).
3. Проверь `npm run build`. Открой экраны, где данные видны (`node scripts/shot.mjs /<маршрут>`), и убедись, что всё выглядит правдоподобно и ничего не разваливается.
4. Коммит `T<n>: демо-данные …`.
