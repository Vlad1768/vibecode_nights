# Telegram-бот «Злой инвестор» (T27)

Telegram-интерфейс тренажёра: `/start` → описание стартапа → 5 вопросов инвестора → оценка по 10 критериям «Стартап как диплом» и 3 совета → новый раунд. Логику вопросов и оценки бот не содержит: он ходит в общий API (T28), который используют и сайт, и бот.

Node.js 22+ без npm-зависимостей (встроенный `fetch`, long polling Telegram Bot API).

## Запуск

```bash
cd bot
BOT_TELEGRAM_TOKEN=<токен от @BotFather> npm start
```

Без `TRAINER_API_URL` бот работает в **демо-режиме** на встроенной заглушке API (`src/api/mock.mjs`): вопросы и баллы условные, об этом бот пишет пользователю.

```bash
npm test   # автономные тесты: без сети и реальных токенов
```

## Переменные окружения

| Переменная | Обязательна | Что это |
|---|---|---|
| `BOT_TELEGRAM_TOKEN` | да | Токен бота. Только из окружения или секрета сервера, не в Git |
| `TRAINER_API_URL` | нет | Адрес общего API T28, например `http://127.0.0.1:8080`. Пусто — демо-режим |
| `TRAINER_API_TIMEOUT_MS` | нет | Тайм-аут запроса к API, по умолчанию 60000 |
| `BOT_HEALTH_PORT` | нет | Порт health-check на `127.0.0.1`: `GET /health` → 200, если опрос Telegram жив |
| `BOT_POLL_TIMEOUT_SEC` | нет | Длительность long polling, по умолчанию 30 |
| `TELEGRAM_API_BASE` | нет | Только для локальной проверки с поддельным сервером |

## Как устроено

| Файл | Что делает |
|---|---|
| `src/main.mjs` | Цикл опроса Telegram, повторы при сбоях сети, корректная остановка по SIGTERM, health-check |
| `src/dialog.mjs` | Диалог без сети: состояние на каждую пару (чат, пользователь), команды, тексты, обработка ошибок |
| `src/telegram.mjs` | Клиент Bot API; длинные ответы делятся на части по 4096 символов |
| `src/api/http.mjs` | Клиент общего API. **Схема временная до контракта T25** — после него меняется только этот файл |
| `src/api/mock.mjs` | Заглушка API той же формы |

Команды бота: `/start`, `/new` (новый раунд), `/retry` (повторить запрос после сбоя), `/cancel`, `/help`.

## Что гарантируется

- **Сессии не смешиваются:** состояние хранится по паре (чат, пользователь), в API передаётся `userId = "tg:<id>"`; API отвечает `SESSION_NOT_FOUND` на чужую сессию. Бот работает только в личных чатах.
- **Сбой API не теряет ответ:** при повторяемой ошибке (сеть, тайм-аут, 5xx, лимит) введённый текст сохраняется, `/retry` отправляет его снова.
- **Нет двойной отправки:** пока обрабатывается сообщение, следующее от того же пользователя отклоняется с просьбой подождать.
- **Понятные ответы** на пустой, слишком длинный (> 4000 символов) и нетекстовый ввод.
- **Секреты:** токен читается только из окружения; журнал (JSON-строки) не содержит токена и текстов сообщений.

## Временная схема API (до T25)

```
POST /api/sessions               {userId, pitch}  → {sessionId, step, totalSteps, question}
POST /api/sessions/{id}/answers  {userId, answer} → {sessionId, step, totalSteps, question}
                                                  | {sessionId, done: true, result}
result = {criteria: [{name, score, max, comment}] ×10, total, max, advice: [строка] ×3}
ошибка: HTTP 4xx/5xx + {error: {code, message}}
code: EMPTY_PITCH, PITCH_TOO_LONG, EMPTY_ANSWER, ANSWER_TOO_LONG, SESSION_NOT_FOUND, RATE_LIMITED, AI_UNAVAILABLE
```

Деплой на сервер — T30 (`deploy/bot/`, `docs/BOT_DEPLOY.md`).
