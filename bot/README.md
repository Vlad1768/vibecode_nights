# Telegram-бот «Злой инвестор» (T27)

Telegram-интерфейс тренажёра: `/start` (приветствие с фото и кнопками «Открыть обучение» / «Приступить к практике») → питч текстом, голосовым или файлом → 5 вопросов инвестора → оценка по 10 критериям «Стартап как диплом» и 3 совета → новый раунд. Логику вопросов и оценки бот не содержит: он ходит в общий API (T28), который используют и сайт, и бот.

Node.js 22+ без npm-зависимостей (встроенный `fetch`, long polling Telegram Bot API).

## Запуск

```bash
cd bot
BOT_TELEGRAM_TOKEN=<токен от @BotFather> npm start
```

Без `TRAINER_API_URL` бот работает в **демо-режиме** на встроенной заглушке API (`src/api/mock.mjs`): вопросы и баллы условные, об этом бот пишет пользователю.

```bash
npm test   # автономные тесты: без сети и реальных токенов
```

## Переменные окружения

| Переменная | Обязательна | Что это |
|---|---|---|
| `BOT_TELEGRAM_TOKEN` | да | Токен бота. Только из окружения или секрета сервера, не в Git |
| `TRAINER_API_URL` | нет | Адрес общего API T28, например `http://127.0.0.1:8080`. Пусто — демо-режим |
| `TRAINER_API_TIMEOUT_MS` | нет | Тайм-аут запроса к API, по умолчанию 60000 |
| `BOT_HEALTH_PORT` | нет | Порт health-check на `127.0.0.1`: `GET /health` → 200, если опрос Telegram жив |
| `GEMINI_API_KEY`, `GEMINI_MODEL` | нет | Распознавание голосовых, PDF и фото (через `integrations/gemini`). Без ключа — только текст, DOCX, PPTX, TXT |
| `BOT_WELCOME_PHOTO` | нет | Фото приветствия: file_id или https-ссылка. Или файл `bot/assets/welcome.jpg` |
| `BOT_POLL_TIMEOUT_SEC` | нет | Длительность long polling, по умолчанию 30 |
| `TELEGRAM_API_BASE` | нет | Только для локальной проверки с поддельным сервером |

## Как устроено

| Файл | Что делает |
|---|---|
| `src/main.mjs` | Цикл опроса Telegram, повторы при сбоях сети, корректная остановка по SIGTERM, health-check |
| `src/dialog.mjs` | Диалог без сети: состояние на каждую пару (чат, пользователь), команды, тексты, обработка ошибок |
| `src/media.mjs` | Голосовое/файл/фото → текст: TXT, MD, DOCX, PPTX локально; голос, PDF, фото — Gemini; длинный документ сокращается до 3500 знаков без выдумок |
| `src/input.mjs` | Сообщение Telegram → вход диалога |
| `src/telegram.mjs` | Клиент Bot API; длинные ответы делятся на части по 4096 символов |
| `src/api/http.mjs` | Клиент общего API по контракту 1.0 |
| `src/api/mock.mjs` | Встроенная заглушка той же формы — демо, если `TRAINER_API_URL` не задан |

Команды бота (меню Telegram ставится при запуске): `/start` (карточка инвестора), `/new`, `/again` (второй раунд по прошлому питчу, итог «было → стало»), `/result`, `/how`, `/retry`, `/cancel`, `/delete` (удалить мои данные в API), `/help`.

## Что гарантируется

- **Сессии не смешиваются:** состояние хранится по паре (чат, пользователь), в API передаётся `userId = "tg:<id>"`; API отвечает `SESSION_NOT_FOUND` на чужую сессию. Бот работает только в личных чатах.
- **Сбой API не теряет ответ:** при повторяемой ошибке (сеть, тайм-аут, 5xx, лимит) введённый текст сохраняется, `/retry` отправляет его снова.
- **Нет двойной отправки:** пока обрабатывается сообщение, следующее от того же пользователя отклоняется с просьбой подождать.
- **Понятные ответы** на пустой, слишком длинный (> 4000 символов) и нетекстовый ввод.
- **Секреты:** токен читается только из окружения; журнал (JSON-строки) не содержит токена и текстов сообщений.

## API

Бот работает по [docs/CONTRACT.md](../docs/CONTRACT.md) версии 1.0: показывает карточку персонажа, факты из питча («что я понял»), реакцию и `notice` перед вопросом, итог с уровнями критериев, сильным/слабым и тремя советами (`advice[i].text`). Ответ шлётся с `step`, поэтому `/retry` безопасен; при `STEP_MISMATCH` и `SESSION_DONE` бот берёт актуальное состояние через `GET`. Текст ошибок API показывается как есть, для `EMPTY_PITCH` — со списком «не хватает».

Разработка против мока контракта:

```bash
node contract/mock-server.mjs &                    # из корня репо
TRAINER_API_URL=http://127.0.0.1:8080 BOT_TELEGRAM_TOKEN=... npm start
```

`test/contract.test.mjs` прогоняет диалог бота через HTTP против этого мока.

Деплой на сервер — T30 (`deploy/bot/`, `docs/BOT_DEPLOY.md`).
