# API «Злой инвестор» (T28)

Один API для сайта (T26) и бота (T27) по [контракту 1.0](../docs/CONTRACT.md). Node.js 22+, без npm-зависимостей. Логика — в [`core/`](../core/README.md), здесь только HTTP, хранение и лимиты.

## Запуск

```bash
node server/index.mjs                          # http://127.0.0.1:8080, режим demo (без модели)
node --env-file=.env.local server/index.mjs    # с GEMINI_API_KEY — режим live
curl http://127.0.0.1:8080/api/health          # {"ok":true,"mode":"demo","version":"1.0"}
```

API занимает тот же адрес, что и `contract/mock-server.mjs`. Бот и сайт переключаются на него без изменений: `TRAINER_API_URL=http://127.0.0.1:8080` для бота, прокси `/api` для сайта.

## Настройки (переменные окружения)

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `PORT`, `HOST` | `8080`, `127.0.0.1` | Где слушать. Снаружи API открывает Caddy по пути `/api` |
| `GEMINI_API_KEY` | — | Ключ модели. Без него режим `demo` |
| `GEMINI_MODEL`, `GEMINI_TIMEOUT_MS` | `gemini-4-argon`, `30000` | Как в [docs/GEMINI.md](../docs/GEMINI.md) |
| `GEMINI_MAX_OUTPUT_TOKENS` | не меньше `2048` | Итог раунда длинный, меньше 2048 API не ставит |
| `DEMO_MODE` | — | `1` — не ходить в модель даже с ключом |
| `AI_FALLBACK` | включён | При сбое модели отвечает демо-движок и помечает ответ `demo: true`. `off` — вместо этого `503 AI_UNAVAILABLE` |
| `DATA_DIR` | `server/.data/` | Файлы `sessions.json` (сессии, 14 дней) и `events.jsonl` (журнал для метрик). Папка в `.gitignore` |
| `CONTENT_FILE` | — | JSON с персонажем, весами и слотами из T29. Формат в [core/README.md](../core/README.md). Без него — условный бизнес-ангел |

Ключ — только в окружении сервера. В ответы, журналы и Git он не попадает.

## Проверка перед пушем

```bash
node --test core/*.test.mjs server/*.test.mjs
```

35 проверок, сеть и ключ не нужны:
- те же сценарии, что у мока: полный раунд, повтор шага, чужая сессия, ошибки ввода, второй раунд, удаление;
- клиент бота `bot/src/api/http.mjs` без изменений;
- все 15 заявок датасета `docs/case/pitch-dataset.md`: 04 — `EMPTY_PITCH`, 09 — `NOT_A_PITCH`, у 13 и 14 есть `notice`, остальные проходят раунд;
- выдуманные моделью цифры, цитаты, «исследования», грубость и уговоры отбрасываются;
- новые питчи не из датасета: без цифр, списком, на английском;
- слабые заявления («1% от рынка», «как Uber для…», «конкурентов нет») не поднимают оценку;
- черновик содержания T29 (`core/content/hype-alchemist.json`) проходит полный раунд;
- плохие советы заменяются годными;
- сбой модели в обоих режимах, двойная отправка, лимиты, перезапуск с сохранёнными сессиями.

## Как устроено

- `index.mjs` — запуск и настройки.
- `handler.mjs` — маршруты контракта:
  - лимиты: 10 новых сессий в час на `userId` и 60 запросов в минуту на IP;
  - ответ API — не дольше 45 с, тело запроса — до 64 КБ.
- `store.mjs` — сессии в памяти с атомарной записью в файл. Старше 14 дней удаляются.
- `limits.mjs` — скользящие окна. IP берётся из `X-Forwarded-For` от Caddy. Бот ходит с того же сервера без этого заголовка, поэтому к нему лимит по IP не применяется, а лимит по `userId` действует.

Журнал `events.jsonl` хранит только события и числа, без текстов питчей и ответов: `session_started`, `round_started {round}`, `answered {step}`, `result_shown {total}`.
