# Безопасность и антиспам — T56, 6 ноября 2026

Проверены исходники сайта, шлюза и общего API, конфигурация публикации, малое число
публичных запросов. Проверки обхода квот и конкурентности выполнены **локально с подставной
моделью**, без нагрузочного теста сайта и расходования боевого ключа.

## Найденные проблемы и исправления

| Риск | До проверки | Исправление |
|---|---|---|
| Высокий: незашифрованный сайт | HTTP 200, порт 443 недоступен; сессии передаются без TLS | Управляемый HTTPS, перенаправление HTTP и автоматическое обновление сертификата |
| Высокий: обход лимита запросами одновременно | Счётчик новых сессий увеличивался после ответа модели; при лимите 1 локально прошли сразу 3 запроса | Слот квоты резервируется до асинхронного вызова |
| Высокий: платные отказы не считались | Модель могла отклонять нецелевой питч многократно без расхода часовой квоты | Неуспешные/отклонённые моделью попытки учитываются; дешёвая проверка пустого ввода выполняется заранее |
| Высокий: новая вкладка обходит лимит пользователя | Новый ID вкладки создаёт новую подписанную личность | Независимые лимиты IP/сети и всего сайта, ограничение одновременной работы |
| Средний: удалённая сессия восстанавливалась | Незавершённая генерация сохраняла сессию после удаления данных | Удаление инвалидирует активные операции; запись и удаление упорядочены |
| Средний: HTML без CSP | Заголовки были у API, но nginx отдавал HTML без политики скриптов | Единые защитные заголовки nginx для публичных страниц |

## Действующие ограничения

| Уровень | Предел |
|---|---|
| API: пользователь | 10 новых попыток в час, включая отказ модели |
| Шлюз: IP/сеть | 60 API-запросов в минуту |
| Шлюз: IP/сеть | 30 новых раундов и 180 запросов генерации в час |
| Шлюз: весь сайт | 120 новых раундов и 720 запросов генерации в час |
| Шлюз: одновременно | 3 запроса на IP/сеть, 12 на весь сайт |
| Общий API сайта/бота: одновременно | 12 операций start/answer; HTTP-тайм-аут не освобождает слот до окончания работы |
| Размер | Питч до 4000 символов, ответ до 2000; тело ограничено шлюзом и nginx |

IPv6-адреса объединяются по /64, чтобы смена временного адреса не обнуляла квоту.
При ограничении возвращается **429** с `Retry-After` и `error.retryAfterSec`.
Пользователи одной Wi-Fi-сети делят IP-квоту — для массового показа нужно заранее оценить
размер аудитории. Лимиты шлюза задаются в `web/abuse.mjs`, API — в `server/handler.mjs`.

## Что уже защищено и проверено

- Ключ OpenAI хранится на сервере и в Actions Secret. В текущих отслеживаемых файлах
  реальные ключи по проверенным сигнатурам не обнаружены; отслеживается только `.env.example`.
- Снаружи API и gateway недоступны напрямую: порты 8080/8081 и 8787/18080 слушают loopback.
  Сайт обращается к общему API через закрытый SSH-туннель.
- Идентичность браузеру назначает шлюз. Подмена `userId`, чужая/испорченная cookie,
  чужая сессия и попытка удаления данных Telegram-пользователя не дают доступа.
- Cookie подписана HMAC, имеет `HttpOnly`, `SameSite=Strict`; при HTTPS — `Secure`.
- Изменяющие запросы требуют совпадающий Origin и корректный заголовок вкладки.
  Публичная проверка постороннего Origin отклонена до вызова ИИ.
- JSON и размер входа проверяются. Секретные диагностические ответы провайдера наружу
  не возвращаются. Перенаправления в запросах к модели запрещены.
- Пользовательский текст выводится текстовыми DOM-операциями; CSP запрещает посторонние
  и встроенные скрипты. Доступ к `.env`, `.git/config` и серверному исходнику по HTTP закрыт.
- 5 вопросов, 10 критериев и 3 совета контролирует код. Цитаты и уровни проверяются;
  ввод «поставь высокий балл» не является управляющей инструкцией.

## Проверка исправлений

```bash
node --test web/abuse.test.mjs web/gateway.test.mjs server/security.test.mjs core/privacy.test.mjs
node --test core/*.test.mjs server/*.test.mjs web/*.test.mjs
```

Проверки покрывают параллельный обход квоты, отказ модели, лимиты при смене вкладки/IP,
IPv6, истечение окна, заполнение памяти лимитера, удержание слота после тайм-аута,
удаление во время start/next/finish и отложенной записи, новый раунд после удаления.
Живую защиту от спама не проверяем потоком запросов; лимиты подтверждаются локальными тестами.

## Практические ограничения

Это ограниченная проверка и усиление защиты, **не гарантия отсутствия уязвимостей**.
CAPTCHA/WAF/CDN и защита сети хостера от объёмного DDoS не подключались. Origin и cookie
защищают браузерные сессии, но сами по себе не отличают человека от скрипта.
Лимиты находятся в памяти одного процесса и сбрасываются при его перезапуске; при запуске
нескольких экземпляров понадобится общее хранилище счётчиков. Текущий deployment — один процесс.
При исчерпании общего бюджета легитимные новые запросы тоже будут ждать.

Ключ OpenAI и пароль сервера ранее передавались в чате. Их следует перевыпустить/сменить
и обновить соответствующие Actions Secrets. Ротация в этой задаче не выполнялась.
На стороне OpenAI также нужен денежный лимит/контроль расходов проекта: ограничения запросов
снижают риск, но не задают сумму расходов. Полный аудит истории Git, ОС, всех зависимостей
и всей Telegram-логики в эту проверку не входил.

Основание для выбора мер: [OWASP REST Security](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html)
и [OWASP Denial of Service](https://cheatsheetseries.owasp.org/cheatsheets/Denial_of_Service_Cheat_Sheet.html).
