# Gemini для VIBECODE NIGHTS

По выбору Германа используется **`gemini-4-argon`**. Настройка модели явная, автоматического переключения на другую модель нет.

## Что готово

Серверный слой провайдера находится в [integrations/gemini/](../integrations/gemini/README.md). Он использует Node.js 24 и встроенный `fetch`, без новых npm-зависимостей. Поддержаны текст и JSON с передаваемой схемой, тайм-аут, отмена, ограничения размера запроса и выхода, безопасные коды ошибок, статистика токенов и типы для TypeScript.

Это серверный слой провайдера из T22. Промпт, схема результата и бизнес-правила передаются вызывающим кодом. Подключение к пользовательскому маршруту, проверка результата, права доступа и хранение относятся к задачам продукта команды.

## Локальные настройки

В корне своей локальной копии создайте `.env.local` по [.env.example](../.env.example). Внесите ключ локально, а не в GitHub, комментарий issue или браузерный код:

```dotenv
GEMINI_API_KEY=<ваш ключ>
GEMINI_MODEL=gemini-4-argon
GEMINI_TIMEOUT_MS=30000
GEMINI_MAX_OUTPUT_TOKENS=1024
```

`.env.local` исключён из Git. Для Next-приложения внутри `web/` те же переменные должны быть в окружении серверного процесса `web` либо в его локальном `web/.env.local`. На хостинге задавайте их как серверные переменные окружения. Не используйте префиксы `NEXT_PUBLIC_` или `VITE_` для ключа.

Команды выполняются из корня репозитория:

```bash
# Только чтение списка моделей; запрос генерации не выполняется.
node --env-file=.env.local integrations/gemini/smoke.mjs

# Один небольшой запрос генерации выбранной модели; расходует доступную квоту.
node --env-file=.env.local integrations/gemini/smoke.mjs --generate

# Автономные тесты: реальные ключи и сеть не используются.
node --test integrations/gemini/client.test.mjs
```

## Пример серверного вызова

Пример импорта дан для скрипта в корне репозитория. В серверном модуле приложения укажите путь к этому же клиенту относительно своего файла:

```js
import { createGeminiClientFromEnv, GeminiError } from './integrations/gemini/client.mjs';

const client = createGeminiClientFromEnv();
try {
  const result = await client.generateJSON({
    system: 'Ответь кратким JSON по переданной схеме.',
    prompt: 'Подготовь короткое приветствие участникам хакатона.',
    schema: {
      type: 'object',
      properties: { text: { type: 'string' } },
      required: ['text'],
      additionalProperties: false,
    },
  });
  // Перед использованием проверьте result.data своей схемой.
  // result.usage содержит сообщённые Google числа либо null, если они неизвестны.
} catch (error) {
  if (!(error instanceof GeminiError)) throw error;
  // Покажите пользователю безопасное сообщение; сохранённый бриф не удаляйте.
  // Для QUOTA предложите повторить позже; не запускайте бесконечные повторы.
}
```

Формат результата, права и правила выбранного кейса проверяются кодом приложения. JSON.parse и схема в запросе к модели не заменяют такую проверку. Общий лимит клиента по умолчанию — 20 000 символов на prompt и system вместе; отдельный лимит пользовательского ввода задаёт приложение.

## Ошибки

| Код | Что означает |
|---|---|
| `CONFIG`, `INPUT` | Некорректные серверные настройки или вход; запроса к API нет |
| `AUTH`, `ACCESS` | Ошибка доступа или необходимые настройки проекта Google |
| `MODEL` | Выбранная модель недоступна |
| `QUOTA` | Google вернул 429; требуется доступная квота для этой модели |
| `PROVIDER`, `NETWORK` | Ошибка Google или сети |
| `TIMEOUT`, `CANCELLED` | Истёк тайм-аут либо вызывающий код отменил запрос |
| `BLOCKED`, `INCOMPLETE`, `RESPONSE` | Заблокированный, обрезанный, пустой или некорректный ответ не принимается как готовый результат |

Клиент не выводит ключ, промпт и сырое сообщение ошибки провайдера. Автоматических повторов нет: `retryable` — подсказка вызывающему коду, а не команда повторять запрос. Тайм-аут или отмена не доказывают, что Google не обработал запрос и не списал квоту.

## Фактическая проверка 6 ноября 2026 года

- Проверка с предоставленным ключом получила HTTP 200 от списка моделей; `gemini-4-argon` присутствует и поддерживает `generateContent`.
- Живая проба генерации получила **HTTP 429 `RESOURCE_EXHAUSTED`**. В деталях Google указаны дневные и минутные ограничения бесплатного уровня для запросов и входных токенов.
- Успешный ответ генерации на этом ключе пока не подтверждён. HTTP 200 при чтении списка моделей не подтверждает доступную квоту генерации.
- 40 автономных тестов прошли: формат запросов/ответов, ошибки, тайм-аут, отмена, JSON, отсутствие автоматических повторов и отсутствие ключа в публичных ошибках.

Чтобы завершить живую проверку, владельцу Google-проекта нужно проверить квоты и условия доступа к выбранной модели в AI Studio. После появления квоты повторите ровно проверку с `--generate`. Модель остаётся `gemini-4-argon`.

## Источники контракта

Клиент использует REST `generateContent`, который Google сейчас относит к legacy-контракту, но продолжает поддерживать. Для этого метода применяются `generationConfig.responseMimeType` и `responseJsonSchema`; поля нового Interactions API с ним не смешиваются. См. [Generate Content API](https://ai.google.dev/api/generate-content) и [структурированный ответ этого метода](https://ai.google.dev/gemini-api/docs/generate-content/structured-output).

Проверка моделей и авторизация: [Models API](https://ai.google.dev/api/models), [ключи Gemini](https://ai.google.dev/gemini-api/docs/api-key). Причины отказов и ограничения: [ошибки API](https://ai.google.dev/gemini-api/docs/generate-content/api-errors), [лимиты Gemini](https://ai.google.dev/gemini-api/docs/rate-limits).
