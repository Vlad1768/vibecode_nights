# Выбор характера инвестора (T51)

По прямому поручению Германа от 6 ноября 2026 сайт предлагает пять характеров перед новым раундом. Это расширение прежнего ограничения `PRODUCT.md` на одного персонажа. Основной контракт 1.0 и клиенты без выбора сохраняются.

## API

`GET /api/personas` возвращает:

```json
{
  "defaultId": "angel",
  "personas": [
    {
      "id": "angel",
      "name": "Золотой локоть",
      "title": "Бизнес-ангел",
      "intro": "Описание персонажа и его манеры",
      "howScored": "Описание общей шкалы",
      "trait": "Прямой и напористый",
      "focus": "Мотивация команды и первые продажи"
    }
  ]
}
```

Каталог всегда содержит `angel`, `corporate`, `grant`, `venture`, `hype-alchemist`. Имена и поведение взяты из `content/investor/investors.json`; серверный каталог лежит в `core/personas.mjs`, чтобы существующий пакет API был самодостаточным. `defaultId` совпадает с ID настроенного содержания, если он есть в каталоге; иначе равен `angel`.

`POST /api/sessions` дополнительно принимает необязательную строку `personaId`. Неизвестные ID, пустая строка и значения другого типа дают `400 BAD_REQUEST`. Клиент выбирает только ID: системный характер, слоты вопросов и веса определяет сервер. Поле `persona` в `Step` и `Done`, включая восстановление через GET, содержит публичную карточку выбранного инвестора в указанной выше форме. Внутренний `character` наружу не передаётся.

`GET /api/persona` остаётся прежней карточкой настроенного содержания. Запрос начала без `personaId` использует прежнего настроенного персонажа, поэтому Telegram-бот менять не требуется. Например, стандартный бот продолжает работать с Олегом, а явный выбор `angel` на сайте включает Золотой локоть.

## Сессия и оценка

Сервер сохраняет полный снимок выбранного содержания вместе с сессией. Каждый следующий вопрос и итог используют этот снимок, включая перезапуск API и изменение его настроек. Параллельные сессии не переключают характер друг другу. Старые сессии без снимка продолжаются с настроенным содержанием и получают снимок при следующем ответе.

Меняются голос инвестора и фокус пятого вопроса: мотивация, внедрение, план и смета, масштабирование, повторный спрос. Все пять вариантов используют одинаковые веса текущего настроенного содержания. Предложенные в `INVESTOR_RUBRIC.md` разные веса этой задачей не вводятся. Остаются ровно пять вопросов, десять критериев и три совета; уровни, доказательства и итог проверяет прежнее ядро.

Если передан `previousSessionId`, новый раунд наследует снимок прошлого. `personaId` можно опустить или повторить прежний ID. Смена характера в сравнительном раунде даёт `400 BAD_REQUEST`; для другого характера нужен отдельный новый раунд без `previousSessionId`.

## Проверка

`node --test core/*.test.mjs server/*.test.mjs` проверяет передачу выбранного содержания движку на старте, каждом вопросе и оценке, параллельные раунды, изоляцию пользователей, восстановление из файла, повтор шага, второй раунд, неверные ID и совместимость старых клиентов. Эти проверки не обращаются к живой модели.
