# Инструкции для `moscow-map/`

Эти правила относятся только к файлам этой папки. Перед работой прочитайте корневые `CLAUDE.md`, `TASKS.md` и `docs/CONTRACT.md`. Соблюдайте регистрацию, отдельный коммит захвата задачи и пуш до начала кода; меняйте только файлы из своей задачи.

По прямому запросу Германа приложение разрабатывается в ветке `feat/moscow-map`, а не в общем `main`. Это исключение записано в журнале решений корневого `TASKS.md`. Для своей доработки создавайте отдельную ветку от актуальной `feat/moscow-map`; базой pull request выбирайте `feat/moscow-map`. Перед пушем выполняйте `git pull --rebase` и проверки. Не используйте force push и не удаляйте чужие изменения.

## Устройство приложения

- `index.html` — единственный файл, необходимый пользователю для запуска. CSS и обычный JavaScript остаются внутри него. Не добавляйте обязательную сборку, npm-пакеты, сервер, ключи API или локальные загрузки через `fetch`, которые ломают запуск по `file://`.
- Карта загружается через официальный iframe OpenStreetMap. Доступ к её DOM ограничен браузером; обновляйте карту через параметры URL iframe, а не через обращение к чужому DOM.
- Поиск фильтрует встроенный каталог. Не выдавайте его за полноценный поиск адресов. Добавляя места, сохраняйте понятные названия, категории и корректные координаты.
- Сохраняйте видимую атрибуцию OpenStreetMap, HTTPS-ссылки, доступные подписи кнопок и русский интерфейс. Не вставляйте пользовательский ввод в `innerHTML`; создавайте текстовые узлы или задавайте `textContent`.
- Новые внешние сервисы и зависимости сначала запишите в журнал решений `TASKS.md`, как требуют корневые правила. Секреты и токены в HTML не размещайте.

## Проверка изменений

Открывайте файл напрямую в браузере. Проверьте перемещение и масштаб карты, выбор места, поиск, категории, пустой результат, сброс, возврат к Москве, полноэкранный режим и узкое окно. Учитывайте недоступность внешней карты: каталог и инструкция о подключении должны оставаться доступны. После изменений описывайте только реально проведённые проверки; не заявляйте проверку на Mac или Windows без запуска на соответствующей системе.

Другому участнику для пуша нужен доступ к GitHub-репозиторию, а не изменение HTML. Без доступа используйте fork и pull request. Параллельные изменения одного HTML-файла заранее согласуйте через задачи и ревью.
