# Москва — карта одним файлом

Тестовое приложение с интерактивной картой OpenStreetMap и небольшим каталогом мест Москвы. Само приложение целиком находится в `index.html`: разметка, стили, данные и JavaScript.

## Запуск на Windows и Mac

Скачайте `index.html` и откройте двойным щелчком в современном браузере, например Chrome, Edge, Firefox или Safari. Нужен интернет для загрузки карты. Node.js, установка пакетов, сервер и API-ключ не требуются.

Карту можно двигать и масштабировать. Выбор места в каталоге показывает его на карте. Поиск и категории работают по встроенному каталогу; поиск произвольных адресов и офлайн-карта не реализованы.

Браузер должен поддерживать JavaScript и WebGL: они нужны встроенной карте OpenStreetMap. Если область карты пустая, используйте постоянную ссылку «Открыть карту отдельно» под каталогом. Из-за ограничений доступа между сайтами приложение не может надёжно определить, отрисовалась ли внешняя карта после загрузки iframe.

## Как другому участнику или Claude продолжить работу

Для работы с исходниками склонируйте ветку приложения:

```sh
git clone -b feat/moscow-map https://github.com/Vlad1768/vibecode_nights.git
cd vibecode_nights
git pull --rebase
git switch -c feat/your-name-map
```

Сначала прочитайте корневые `CLAUDE.md`, `TASKS.md`, `docs/CONTRACT.md`, а также местные `AGENTS.md` и `CLAUDE.md`. Зарегистрируйте свою задачу в конце таблицы `TASKS.md` со статусом `свободна`; затем захватите её отдельным коммитом и сразу запушьте, как требуют правила команды. Не начинайте код до успешного пуша захвата. Укажите в задаче конкретные файлы внутри `moscow-map/`, чтобы два агента не редактировали их одновременно.

Дорабатывайте приложение в своей ветке, выполняйте проверки ниже, делайте небольшие коммиты. Перед каждым пушем выполните `git pull --rebase`, повторите нужные проверки и запушьте свою ветку. Затем откройте pull request с базовой веткой **`feat/moscow-map`**. Общий `main` для этого тестового приложения менять не нужно: отдельная ветка выбрана по запросу Германа и записана в журнале решений `TASKS.md`.

Для пуша другой участник должен принять приглашение в репозиторий на [GitHub Notifications](https://github.com/notifications). HTML-файл не выдаёт права на GitHub. Если доступа нет, можно сделать fork и отправить pull request из своего репозитория. Запись о захвате в личной ветке не резервирует файлы в общей ветке: перед параллельными правками согласуйте задачу с владельцем карты через ревью её коммита или pull request.

Пример запроса другому Claude:

> Прочитай правила в корне и в `moscow-map/`. Создай свою ветку от актуальной `feat/moscow-map`, зарегистрируй и захвати отдельную задачу по правилам команды. Доработай карту в пределах файлов этой задачи, сохрани запуск одним HTML-файлом и проверь её в браузере. Подготовь pull request в `feat/moscow-map`.

## Проверка перед передачей

- Откройте `index.html` двойным щелчком: карта должна загрузиться, перемещаться и масштабироваться.
- Найдите место по названию, смените категорию и выберите результат: выбранное место должно появиться на карте.
- Введите отсутствующее название: должен появиться понятный пустой результат; сброс должен вернуть каталог.
- Проверьте возврат к Москве и полноэкранный режим, включая выход из него.
- Уменьшите ширину окна до размера телефона: поиск, список и карта должны оставаться доступными.
- При недоступности OpenStreetMap интерфейс каталога должен оставаться доступным; приложение должно сообщать, что для карты нужен интернет, и предлагать открыть её отдельно.

Эти пункты — инструкция для ручной проверки, а не заявление о проведённых тестах на всех операционных системах.

## Где менять приложение

В `index.html` стили находятся в `<style>`, интерфейс — в HTML, а каталог мест и обработчики — в `<script>`. Сохраняйте эти разделы вместе: пользователь должен по-прежнему получать один переносимый файл. Не убирайте атрибуцию OpenStreetMap и не закрывайте её элементами интерфейса.
