# Сайт «Злой инвестор» — T26

Первый веб-прототип: питч, пять вопросов, десять критериев и три совета. Пользователь поручил начать верстку до готовности общего контракта T25 и отдельно подключить Gemini Argon. Во время разработки команда опубликовала контракт T25 версии 1.0 и общее ядро T28. Первая выгрузка пока использует временный адаптер сайта; согласование шкалы и переход на общий API остаются следующим этапом T26. Она не является завершённой интеграцией T32.

## Запуск

Требуется Node.js 24. Сторонних npm-зависимостей и сборки нет.

Из корня репозитория:

```sh
node --env-file=.env.local web/server.mjs
# http://127.0.0.1:8787
```

Без ключа работает явный деморежим; живые запросы возвращают понятную ошибку настройки. Для локальной проверки демо достаточно `node web/server.mjs`.

Переменные сервера: `GEMINI_API_KEY`, `PORT` (8787), `HOST` (127.0.0.1). Модель в адаптере фиксирована: `gemini-4-argon`. Секрет хранится вне репозитория, не входит в HTTP-ответы и клиентский JavaScript.

## Сценарий и оценка

Gemini получает исходный питч и предыдущие ответы, задаёт один вопрос за ход. После пятого ответа сервер проверяет структуру: десять уникальных критериев, ровно три совета, целые баллы 0–10. Сумму до 100 вычисляет код. Предварительные уровни: 0 — данных нет, 1–3 — предположения, 4–6 — объяснение и отдельные подтверждения, 7–8 — убедительные данные с пробелами, 9–10 — сильные проверяемые доказательства. Веса равны. Контракт T25 задаёт уровни 0–3 и веса персонажа: в этой первой независимой версии ещё остаётся предварительная шкала 0–10. Её нужно заменить вместе с подключением общего ядра и содержанием T29.

Деморежим использует фиксированный учебный пример StudySpot. Его результат не является оценкой пользовательского ввода; переключение в демо только явное. При сбое Gemini сервер не заменяет ответ примером.

Питч и ответы передаются Google только в режиме ИИ. Черновик и состояние интерфейса сохраняются в `sessionStorage` текущей вкладки. Серверные раунды хранятся в памяти до часа неактивности и исчезают при перезапуске процесса. После истечения сессии нужно начать новый раунд; клиентский черновик сохраняется. Лимиты: 30 запросов API в час на IP, до двух одновременных генераций. Секретная HttpOnly cookie связывает раунд с браузером.

## API веб-прототипа

- `GET /api/health` — наличие настроенного клиента и имя модели. `ready: true` не доказывает доступную квоту генерации.
- `POST /api/session` с `{pitch}` — `{sessionId, step:1, totalSteps:5, question:{title,text,hint}}`.
- `POST /api/session/:id/answer` с `{answer,step}` — следующий вопрос либо `{done:true,result:{summary,score,maxScore,criteria,tips}}`.
- Ошибки: `{error:{code,message}}`. Публичные сообщения не содержат ключей или сырых ошибок провайдера.

POST принимает JSON того же origin. Питч ограничен 4000 символами, ответ — 2000. Успешно принятый ответ можно повторить с тем же шагом и текстом без повторной генерации.

## Размещение

По прямому поручению Германа сервер сайта — `194.67.88.222`, отдельно от сервера Telegram-бота. Домен — `fightinvestor.ru`.

На Ubuntu установлен nginx; Node.js 24 установлен из официального архива с проверкой SHA256. Это серверные зависимости, новых npm-зависимостей нет. Публичные файлы: `/var/www/fightinvestor/{index.html,styles.css,app.mjs,demo.mjs}`. Серверные файлы: `/opt/fightinvestor/web/` и `/opt/fightinvestor/integrations/gemini/client.mjs`. Окружение: `/etc/fightinvestor.env`, root, режим 600. Сервис `fightinvestor.service` работает от отдельного пользователя `fightinvestor`, слушает только `127.0.0.1:8787`. nginx проксирует `/api/` с собственными Host и forwarded headers.

Для DNS в REG.RU: A `@` → `194.67.88.222`, по необходимости CNAME `www` → `fightinvestor.ru`. HTTPS выпускается после подтверждения DNS. Пароли и ключи нельзя помещать в публичный каталог, аргументы команд или Git.
