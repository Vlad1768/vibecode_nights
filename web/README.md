# Сайт «Злой инвестор» / Investfy

Статический интерфейс общего тренажёра: питч → пять вопросов → десять критериев с цитатами → три совета. Браузер и Telegram-бот используют `server/` и `core/` по контракту 1.0. Веб-интерфейс показывает персонажа, факты из питча, реакции на ответы и второй раунд со сравнением результата.

## Дизайн

По поручению пользователя оформление адаптировано из визуального языка [Wild / Craft, engineered](https://craft.wild.as/): сетка, крупные заголовки, тонкие разделители, прямоугольные кнопки и движущаяся пиксельная волна. По последнему уточнению пользователя палитра тёмная, как в презентации кейса: почти чёрный фон, светлый текст и оранжевые акценты. Внешние изображения, шрифты, библиотеки и код референса не загружаются.

Сначала рассчитана мобильная компоновка: основной переход в тренажёр на первом экране, этапы 2×2, формы и результаты в одну колонку. На широком экране — две колонки и пример диалога. Волна работает на canvas до 30 кадров/с, останавливается вне экрана и в скрытой вкладке. Есть кнопка паузы; `prefers-reduced-motion` оставляет статичное оформление. Без motion JavaScript содержание и формы остаются доступными.

## Запуск

Node.js 22+ для общего API, Node.js 24 используется на сервере сайта. npm-зависимостей и сборки нет.

Терминал 1, Linux:

```sh
node server/index.mjs
# http://127.0.0.1:8080 — учебное ядро без ключа
```

На Windows текущая точка входа `server/index.mjs` требует явного импорта:

```sh
node --input-type=module -e "import {createServer} from 'node:http'; import {createApp} from './server/index.mjs'; const app=createApp(); createServer(app.handler).listen(8080,'127.0.0.1');"
```

Терминал 2:

```sh
node web/gateway.mjs
# http://127.0.0.1:8787
```

Gateway: `TRAINER_API_URL` (по умолчанию `http://127.0.0.1:8080`), `HOST` (`127.0.0.1`), `PORT` (`8787`), `WEB_COOKIE_SECRET`. В production постоянный `WEB_COOKIE_SECRET` не короче 32 символов обязателен; локально случайный ключ живёт до перезапуска. Ключ Gemini нужен только общему API.

## Общий API и идентичность

Сайт вызывает `/api/persona`, `/api/sessions`, `/api/sessions/{id}/answers` и GET текущей сессии. После сетевого сбоя или перезагрузки GET восстанавливает подтверждённый сервером шаг. Повторная отправка содержит номер `step`; второй раунд передаёт `previousSessionId`. Весь расчёт — на общем сервере: уровень 0–3 × вес / 3; показываются веса, цитаты и итог из 100. Вопросы, баллы и советы gateway не генерирует.

Публичный gateway допускает только маршруты веб-клиента и назначает случайный `web:<UUID>`. Пользовательский `userId` из тела или URL игнорируется. Подписанная HttpOnly SameSite cookie подтверждает эту идентичность. `X-Web-Client` — случайная метка вкладки в sessionStorage, которая только выбирает отдельное имя cookie: это не userId и не полномочие. Так параллельно открытые вкладки не перезаписывают доступ друг друга. Подпись привязана к метке, секрет остаётся на сервере. Для будущей кнопки удаления доступен только `DELETE /api/users/me`; произвольные идентификаторы, в том числе Telegram, не принимаются.

API не должен быть открыт напрямую в интернет: его контракт доверяет `userId` вызывающего сервиса. Gateway ограничивает origin и размер запросов, время ожидания, маршруты и публичные файлы; не передаёт браузеру диагностику провайдера. nginx должен перезаписывать forwarded headers адресом реального клиента.

## Учебные режимы и ошибки

«Посмотреть демо» — отдельный фиксированный пример StudySpot с явной подписью, без обращения к модели; ответы посетителя в нём не оцениваются. Его историческая иллюстративная шкала 0–10 подписана отдельно от шкалы общего API.

Если общий сервер настроен в `demo`, сайт показывает это до отправки и на каждом учебном раунде. При ответе `503` frontend не подставляет демо: текст пользователя и черновик сохраняются, доступна повторная отправка. Если API сам возвращает `demo: true`, это явно показывается в интерфейсе. `health.mode=live` означает конфигурацию режима, а не проверенную квоту. Существующий API Ивана обнаружен работающим в `demo`; подключение сайта сохраняет его конфигурацию и не включает модель с исчерпанной квотой.

6 ноября 2026 последняя подтверждённая живая генерация Gemini Argon вернула `429 QUOTA`. Перенос API на общий сервер сам по себе квоту не исправляет.

## Размещение

По поручению пользователя сайт остаётся на `194.67.88.222` (nginx), а общий API — уже работающий на сервере Telegram-бота `45.147.28.43`. Приватный SSH-туннель соединяет gateway `127.0.0.1:8787` → `127.0.0.1:18080` → API `127.0.0.1:8080` у Ивана. Существующий бот обращается к тому же API локально. Режим `attach` не изменяет код, ключи, окружение или службы API и бота. Workflow и откат описаны в [deploy/web/README.md](../deploy/web/README.md).

Пароль сайта хранится в Actions Secret `SITE_SERVER_PASSWORD`; адрес и логин — в Variables `SITE_SERVER_HOST`, `SITE_SERVER_USER`. `BOT_*` — отдельные настройки.

Домен `fightinvestor.ru`: при проверке 6 ноября 2026 публичный DNS возвращал NXDOMAIN для NS и A (ответ от зоны ru), то есть домен не делегирован. В REG.RU нужно проверить точное имя, активную регистрацию и NS. После делегирования: A `@` → `194.67.88.222`, CNAME `www` → `fightinvestor.ru`; затем выпуск HTTPS. Сейчас рабочий адрес — HTTP по IP.

`web/server.mjs` и его тесты сохранены как предыдущий самостоятельный прототип для истории/отката. Текущий frontend с ним несовместим: он использовал `/api/session` и собственную шкалу. Для нового frontend запускайте `web/gateway.mjs`.

## Проверка

```sh
node --test web/demo.test.mjs web/gateway.test.mjs web/app.test.mjs
node --test core/*.test.mjs server/*.test.mjs
node --check web/app.mjs
node --check web/motion.mjs
```

Тесты gateway и frontend используют настоящее общее ядро в учебном режиме: полный раунд, изоляция вкладок/пользователей, отказ подмены Telegram ID, HMAC/expiry/CSRF, повтор шага, GET-восстановление, второй раунд, тайм-аут, отказ провайдера без подмены демо и отмена запроса при переключении режимов. Браузерная проверка включает мобильную компоновку и полный путь 5/10/3.
