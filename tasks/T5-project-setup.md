# T5. Выбрать маршрут и подготовить структуру проекта

Зависимость: T13. Статус и владелец: [TASKS.md](../TASKS.md).

**Результат:** `docs/project-route.md`, перечень нужных файлов и начальная структура выбранного примера.

## Работа

- С владельцем выбрать один маршрут: Telegram-бот, статический сайт либо сайт с серверной частью. Совместный Compose из презентации не обязывает запускать три службы.
- Описать пользователя, одно действие, ожидаемый ответ и способ проверки. Для бота отдельно решить, останется ли он эхо-ботом или после успешного эхо потребуется ИИ.
- Для бота запланировать `bot/bot.py` и `bot/requirements.txt`; для статики — `site/index.html`; для Node — `web/server.mjs`, `web/public/index.html`, `web/package.json` и lock-файл.
- Перечислить общие настройки: `.env.example`, `.gitignore`, последующие Dockerfile, `compose.yaml`, Caddyfile и инструкцию. Отметить неприменимые файлы, не создавать лишние службы.
- Записать внешние вводные: Telegram-токен и ID для бота; домен для сайта; сервер и доступы для постоянной работы. Сами секреты в документ не включать.

## Готово, когда

Владелец подтвердил маршрут и границы. Есть вход, ожидаемый результат, дерево файлов, требования к окружению и список недостающих вводных. Понятно, что проверяют локально в T6 и что требует реального VPS. Покупки, публикация и установка инфраструктуры этим решением не выполняются. Версии и команды из презентации предстоит проверить перед реализацией.

Основание: физические слайды 22–23 (П01–П02), 43 (П22), 51 (П30).
