# T11. Проверить резервную копию, обновление и откат

Зависимость: T9. Статус и владелец: [TASKS.md](../TASKS.md).

**Результат:** `docs/backup-and-rollback.md`, проверенная резервная копия и протокол восстановления в отдельной тестовой среде.

## Работа

- Определить, что реально хранит выбранный пример: файлы данных, исходники, Compose и конфигурацию. Эхо-бот не сохраняет историю по умолчанию; статике без состояния достаточно сохранить файлы сайта и исходники.
- Для файлового состояния получить согласованную копию, остановив только процессы записи нужных служб. Использовать уникальное имя с датой, сохранить копию вне VPS и проверить возможность её прочитать.
- Для базы данных выбрать согласованный способ экспорта, например штатный dump; не архивировать работающие файлы базы обычным tar. Секреты хранить отдельно.
- Восстановить копию в тестовом окружении, проверить владельцев папок и реальный ответ приложения. Рабочие данные не заменять учебным архивом.
- Сохранить старые код, Compose и образ версии v1; выпустить v2 и проверить сценарий. Для отката вернуть согласованный комплект прежней версии без пересборки старого образа.
- Для статики проверить возвращение предыдущей папки сайта. Учесть, что откат образа не отменяет миграции или изменения формата данных.

## Готово, когда

Восстановление и возврат версии реально воспроизведены, записаны места хранения, время проверки и результат. Предыдущие данные и образы сохранены до приёмки. Инструкция использует только существующие службы и не требует запуска всех вариантов практикума.

Основание: физические слайды 48–49 (П27–П28), 51 (П30).
