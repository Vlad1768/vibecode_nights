# T8. Упаковать приложение и перенести на VPS

Зависимости: T6, T7. Статус и владелец: [TASKS.md](../TASKS.md).

**Результат:** нужные Dockerfile и `.dockerignore`, `compose.yaml`, безопасный `.env.example`, выбранный Caddyfile, `docs/release.md` и подготовленная папка проекта на VPS.

## Работа

- Описать только выбранные службы. Бот собирается из `bot/`, Node — из `web/`; готовую статику раздаёт Caddy без службы web.
- Для программы проверить сборку и production-команду, запуск непривилегированным пользователем. Не подменять production start командой dev.
- В Compose предусмотреть `restart: unless-stopped`, ограничение размера и количества логов. Для записываемых данных использовать отдельные папки с владельцем UID соответствующего контейнера.
- Для сайта сохранить сертификаты и конфигурацию Caddy в named volumes. Только Caddy публикует 80/443; порт web 3000 остаётся внутри Docker-сети, бот не имеет входящих портов.
- Перенести исходники или архив без `.env`, `.git`, виртуального окружения, `node_modules`, рабочих данных и резервных копий. Архив создавать вне упаковываемой папки.
- Создать реальные секреты отдельно на сервере, не перезаписывая существующий `.env`. Не выводить значения конфигурации в отчёт.

## Готово, когда

Сборка выбранной программы и проверка Compose без вывода секретов успешны. Проверены содержимое выпуска, пути, права данных и отсутствие ключей в Git, образах и архиве. На VPS известна точная версия кода и инструкция запуска. Неприменимые службы не добавлены; их наличие в учебном полном Compose не является требованием.

Основание: физические слайды 34–37 (П13–П16), 39–44 (П18–П23).
