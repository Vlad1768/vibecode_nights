# Что действительно описано в презентации

Источник: `AI-development-minimal-with-screencasts.pptx`, 53 слайда. Прочитаны текст слайдов и заметки докладчика. Оригинальная презентация и встроенные видео в репозиторий не загружались.

## Основная часть

Слайды 1–16 объясняют разработку с ИИ от идеи до пилота: сначала выполнить процесс вручную на нескольких примерах, определить хороший результат, описать проект и законченный пользовательский сценарий, проверить исключения, выпустить и измерить пользу. Пример коммерческого предложения по брифу иллюстрирует подход и не определяет продукт команды.

В слайде 16 предложено выбрать ближайший проверяемый шаг собственного проекта. В презентации нет фиксированного продукта и срока сдачи для нашей команды.

## Самостоятельный практикум

Слайды 22–53 — отдельное скрытое продолжение с командами и полными файлами в заметках. Ниже указаны физические номера слайдов; например, слайд 22 соответствует П01, слайд 51 — П30.

## Важные различия

- Заметки слайда 23 содержат копируемый запрос на набор `bot/`, `site/` и `web/`. Слайды 22, 43 и 45 разрешают запускать только выбранные службы.
- Polling-бот не требует домена и входящего порта. Один токен должен обслуживать один polling-процесс.
- Статический сайт не требует Node. Для него проверяют главную страницу; `/healthz` относится к серверному примеру.
- API модели подключается отдельным шагом после работающего эхо-бота. Ключ находится на серверной стороне, действуют ограничения запросов и расходов.
- Команды восстановления предназначены для отдельной тестовой копии. Перезагрузка VPS затрагивает все его проекты и требует согласования.
- Возврат версии кода не откатывает изменения базы данных. Для статики сохраняют исходники и файлы сайта; для данных нужна согласованная копия.
- Размер VPS, поставщик модели, адреса и версии пакетов — учебные примеры. Перед реализацией проверяются актуальная документация и реальные условия.
- Видео Lusion и Cuberto на слайде 3 — визуальные референсы, не перечень обязательных функций.
