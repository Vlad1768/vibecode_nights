# T9. Запустить выбранную службу и проверить доступ

Зависимость: T8. Статус и владелец: [TASKS.md](../TASKS.md).

**Результат:** работающий выбранный сервис и `docs/deployment.md` с адресом или Telegram-ботом, версией, временем выпуска и доказательствами проверки.

## До начала

Нужны серверные доступы и поручение на запуск. Для сайта владелец предоставляет домен и права на DNS; для polling-бота домен не требуется. На действующем VPS повторно проверить занятые порты и чужие службы. Все значения примеров заменить фактическими.

## Работа

- Проверить конфигурацию без вывода секретов и запустить только нужный маршрут: bot; Caddy для статики; web и Caddy для серверного сайта.
- Для бота остановить локальный экземпляр с тем же токеном. Проверить `/start` и эхо от разрешённого ID; отдельно убедиться в ограничении доступа. Статус контейнера Up сам по себе недостаточен.
- Для сайта проверить A-запись и возможную AAAA: они должны вести к этому VPS. Выбрать один Caddyfile: файловая раздача либо reverse proxy на внутренний `web:3000`.
- Проверить получение HTTPS-сертификата и открытие сайта извне. У Node проверить `/healthz`; у статики — главную страницу, без выдуманного health endpoint.

## Готово, когда

Реальный внешний запрос успешен, бот либо сайт работает после закрытия локального процесса автора. Зафиксированы логи нужных служб, ограничения и команды управления без секретов. DNS, сертификат и ответ приложения различаются как отдельные проверки; чужие проекты сохранены.

Основание: физические слайды 38 (П17), 42–45 (П21–П24), 51 (П30).
