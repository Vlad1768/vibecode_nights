# Как резать задачи для 5 параллельных агентов

## Правила
1. **Одна задача — 20–40 минут работы Claude** и один видимый результат, который можно проверить за минуту. Пример: «/catalog показывает карточки из `api.getProducts()`, фильтр по категории работает, есть пустое состояние».
2. **«Где» не пересекается** с другими задачами. Общие файлы (`layout.tsx`, `types.ts`, `api.ts`, `globals.css`) правят только задачи ведущего.
3. **Первая волна (≥6 задач) без зависимостей.** Моки и контракт позволяют фронту не ждать бэк.
4. **Режь вертикально: по экранам и шагам демо-сценария**, а не по слоям. «Экран заказа целиком» лучше, чем «все формы».
5. **Порядок строк повторяет демо-сценарий**: сначала главный путь, в конце «(бонус)».
6. **Текст задачи** — что сделать, критерий готовности и ссылка на раздел контракта, в 1–3 предложениях. Человек и Claude должны понять задачу без вопросов. Подробности — в CONTRACT.md и PRODUCT.md, а не в ячейке таблицы.
7. В колонке «Зависит от» пиши ID через запятую или `—`. Статус — `свободна`.

Получилось меньше 10 задач — значит, задачи слишком крупные. Больше 15 — люди не успеют, перенеси лишнее в «(бонус)».

## Распределение по людям (подсказка ведущему)
- 2 фронта: T1–T4, потом T10.
- Бэк/AI: T5, T8.
- Продукт/питч (может быть человек с Codex): T7, T6, затем ревью и QA.
- Ведущий: каркас, T9, T11, разбор блоков.
Закреплять задачи за людьми не нужно: каждый берёт следующую свободную через `/next`. Подсказка нужна только, чтобы на старте все не схватили фронт.
