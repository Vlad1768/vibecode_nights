# /kickoff — каркас, контракт и задачи за 20 минут

Ты работаешь на ведущего. Пока ты здесь, четыре человека ждут. Цель: **через 20 минут в `main` лежит каркас, который собирается, а в `TASKS.md` есть ≥6 задач без зависимостей.** Ты не пишешь фичи. Твоя задача — сделать так, чтобы все остальные могли писать фичи одновременно и не мешали друг другу.

Вход: `$ARGUMENTS` — текст кейса, путь к файлу с кейсом и/или выбранная идея. Чего не хватает, спроси **одним** вопросом через AskUserQuestion (рекомендуемый вариант ставь первым). Больше одного раунда вопросов не задавай: где можно, бери разумное умолчание и записывай его в документ.

Таймер ориентировочный. Если шаг затягивается, упрости его, но не пропускай.

## 0. Синхронизация (30 сек)
`git pull --rebase`, затем прочитай `CLAUDE.md`, `TASKS.md`, `docs/CONTRACT.md`.

## 1. Продукт → `docs/PRODUCT.md` (≤4 мин)
Если идея не выбрана, проведи сжатый `/ideate` (`.claude/skills/ideate/SKILL.md`): 3 концепта, рекомендация, один вопрос человеку.

```markdown
# <Название> — <что это, одной строкой>
## Для кого и какая боль            (конкретная персона и ситуация, цифра боли, если есть)
## Демо-сценарий (90 секунд)        (5–7 шагов: что жюри увидит на экране)
## Wow-момент                       (одна вещь, после которой жюри говорит «о!»)
## Что настоящее, а что мок
## Не делаем                        (явный список, чтобы никто не расползся)
## Критерии жюри → чем закрываем
```
Демо-сценарий — главный документ проекта: каждая задача должна обслуживать один из его шагов.

## 2. Стек и каркас (запусти в фоне сразу)
По умолчанию бери **пресет A** из [stacks.md](stacks.md): Next.js + TypeScript + Tailwind + shadcn/ui в папке `web/`. Другой стек выбирай, только если кейс этого прямо требует: Python/ML, Telegram-бот (см. там же).
Команды установки запускай **в фоне** (Bash с `run_in_background`): `npm install` идёт около 2 минут, и это время уходит на шаги 3 и 5. После установки сделай правки из раздела «Обязательные правки после каркаса» в stacks.md. Без них сборка упадёт у первого же, кто напишет `new Date()`.

## 3. Контракт → `docs/CONTRACT.md` (≤5 мин)
- **Модели данных** в виде TypeScript-типов, один в один как в `web/src/lib/types.ts`. Деньги — `number` в рублях, даты — ISO-строки, id — строки.
- **Функции доступа к данным** (`web/src/lib/api.ts`): сигнатура плюс пример ответа в JSON. Фронт ходит только через них.
- **API-роуты** (если есть): метод, путь, тело запроса и ответа, у каждого пример JSON.
- **Маршруты**: таблица «URL → что на экране → ID задачи».
- **Общие файлы и владельцы**: layout, types, api, globals.css — у ведущего.
Правило: всё, что показывает UI, есть в контракте. Каждый пример JSON должен быть правдоподобным, а не `"string"`.

## 4. Общие заготовки (≤5 мин, когда установка закончилась)
Создай файлы, которые иначе будут править все одновременно:
- `web/src/lib/types.ts` — типы из контракта.
- `web/src/data/mock.ts` — 5–10 правдоподобных записей на сущность. Подробные данные потом сделает задача по `/demo-data`.
- `web/src/lib/api.ts` — async-функции с сигнатурами из контракта. Пока они возвращают моки с `await delay(300)`, чтобы были видны лоадеры. Позже бэк заменит реализацию внутри, и фронт менять не придётся.
- `web/src/app/layout.tsx` — шапка с навигацией по **всем** маршрутам из контракта, `lang="ru"`, шрифты из DESIGN.md с `subsets: ["latin", "cyrillic"]`, `metadata.title`, `<Toaster />`, если подключён sonner.
- `page.tsx`-заглушка для каждого маршрута: заголовок и «Скоро: <что здесь будет>». Тогда маршруты существуют, навигация работает, а каждая задача владеет ровно своей папкой.
- Если в продукте есть AI: `web/src/lib/ai.ts` из `.claude/skills/ai-feature/templates/ai.ts` и `npm i @anthropic-ai/sdk zod`.
- `web/.env.example` со строками `ANTHROPIC_API_KEY=`, `DEMO_MODE=0`, `AI_MODEL=claude-opus-5-5`.

## 5. Дизайн → `docs/DESIGN.md` (≤3 мин)
Выбери направление из `.claude/skills/polish/directions.md` под аудиторию продукта. Если два направления подходят одинаково, спроси человека, приложив к каждому одну строку описания. Перенеси токены в `globals.css`, шрифты — в `layout.tsx`. В DESIGN.md запиши: направление, токены, шрифты, радиусы, отступы, тени, «фирменную деталь», тон текстов интерфейса и правило «компоненты из `components/ui/` руками не правим».

## 6. Задачи → `TASKS.md` (≤4 мин)
Правила нарезки и типовой набор — в [slicing.md](slicing.md). Строки-плейсхолдеры `T1`/`T2` с «…» замени настоящими задачами, R-строки разминки не трогай. Нужно 10–15 задач, из них ≥6 без зависимостей.
Заполни раздел «Проект» в `CLAUDE.md` (что делаем, стек, как запустить, проверка перед пушем) и добавь строку в «Журнал решений» в `TASKS.md`.

## 7. Проверка и пуш (≤2 мин)
1. `cd web && npm run build` должен пройти. Если есть время, запусти dev-сервер в фоне и выполни `node scripts/shot.mjs /`, чтобы глазами посмотреть главную.
2. В `git status` не должно быть `.env.local` и `node_modules`.
3. `git add -A && git commit -m "kickoff: каркас, контракт, задачи"`, затем `git pull --rebase`, затем `git push`.

## 8. Объяви команде
Выведи текст, который человек вставит в чат команды:
```
Каркас в main. Всем: git pull && cd web && npm install && cp .env.example .env.local
Своему Claude: /next <Имя>
Продукт — docs/PRODUCT.md · Контракт — docs/CONTRACT.md · Дизайн — docs/DESIGN.md
```
Дальше предложи ведущему сразу подключить деплой (`/deploy`): 5 минут сейчас избавят от паники в конце. Потом он берёт свои задачи (интеграция, smoke).

## Чего не делать
- Строить идеальную архитектуру, задавать много вопросов или писать фичи вместо заглушек.
- Давать двум задачам один файл. Оставлять в контракте поля без примеров.
- Нарезать задачи по слоям («все кнопки», «все стили») вместо экранов и шагов сценария.
